# The ISP Reality RFC Series

A collection of satire RFCs documenting standardized operational behavior commonly observed when interacting with Internet Service Providers.

These documents follow IETF-style formatting and describe real-world support workflows, troubleshooting methodologies, and customer experience patterns.

All RFCs in this repository are **informational**, **non-normative**, and **painfully accurate**.

This series is **actively maintained** and updated on a regular basis.  
Additional documents are continuously being drafted based on newly observed ISP behaviors.  
RFC **9011–9020** are currently in development and will be published soon.

# Compliance

An ISP is considered fully compliant with this RFC suite if:

- Tickets are acknowledged but not resolved  
- Reboots are requested multiple times  
- Monitoring always shows green  
- Speedtests only work on ISP servers  
- Static IPs are unavailable  
- Static IPs blamed for instability  
- Routers require emotional recovery  
- Backend dashboards override reality  
- Chatbots replace human support  
- Outages become maintenance  
- Upstream is blamed  
- Customers provide cables  
- Issues reoccur weekly
