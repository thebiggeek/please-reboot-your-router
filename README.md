# The ISP Reality RFC Series

A collection of satire RFCs documenting standardized operational behavior commonly observed when interacting with Internet Service Providers.

These documents follow IETF-style formatting and describe real-world support workflows, troubleshooting methodologies, escalation procedures, and customer experience patterns.

All RFCs in this repository are **informational**, **non-normative**, and **painfully accurate**.

This series is **actively maintained** and updated on a regular basis.
Additional documents are continuously being drafted based on newly observed ISP behaviors, technician interactions, and operational escalation patterns.

# Compliance

An ISP is considered fully compliant with this RFC suite if:

* Tickets are acknowledged but not resolved
* Reboots are requested repeatedly
* Monitoring always shows green
* Speedtests only work on ISP servers
* Static IPs are blamed for instability
* Routers require emotional recovery
* Backend dashboards override reality
* Customers are treated as ID10Ts
* Temporary fixes become permanent infrastructure
* Responsibility is continuously transferred
* Escalations never reach ownership
* Outages become maintenance windows
* Upstream is blamed
* Customers provide LAN cables
* Issues reoccur weekly
* Tickets eventually auto close
